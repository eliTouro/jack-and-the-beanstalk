# Testing the two production checks

The brief asks for two things to hold, and to test them on several different uploads:

1. **Likeness**: the face in the output is recognizably the face that was uploaded.
2. **Scene fidelity**: the picture shows what its caption says.

Offline unit tests (`npm test`) cover the plumbing: input validation, settings sanitizing, and the rule that the caption sent to the model is the caption shown. The two checks above can only be judged by looking at real outputs, so that's what this file records.

## Method

- **Faces.** Seven faces of people who do not exist (`test-faces/`): six StyleGAN faces from thispersondoesnotexist.com, plus one dark-skinned adult generated by the image model itself, because none of 50 StyleGAN candidates had dark skin. They vary in age (child to 60+), gender presentation, skin tone, hair, glasses, beard and earrings. See `test-faces/README.md`.
- **Pipeline.** Each face goes through exactly what the web app does: one cartoon call, then one call for each scene, with the original photo and the cartoon as references. Settings were the app defaults (Storybook watercolor, subtle, vivid, fine lines).
- **One call per command.** `scripts/try.mjs` makes exactly one model call per run, with no loops. Every call was made by hand and its output viewed.
- **Judging.** I looked at each result next to its photo. *Likeness* is a pass if hair, hair color, skin tone, eye color, face shape, age, gender presentation, glasses and facial hair all read as the same person. *Scene fidelity* is a pass if every element in the caption is visible. These are my own judgments, not a face-recognition score.

## Known limitation (honest)

Likeness does **not** fully hold for face 7 in the scene images, so I'm not claiming it holds for every possible upload. The model reads the story's "Jack" as a boy, and when the figure is small it tends to drop age and gender cues. This showed up mildly on face 3 and strongly on face 7. Two further prompt attempts (a larger face, and an explicit "never turn a woman or older person into a boy" rule) did not fix face 7, and I reverted them so the shipped prompt is the one tested above. Running at `high` quality fixed the earring and looked slightly more adult, but one image took 73 s and costs several times more, so it's not the default. The cartoon portrait step does hold for all seven faces, and it's the first image users see.

## Prompt iteration log

| Version | Change | Result |
|---|---|---|
| v1 | Baseline on `gpt-image-1-mini`, "medium" exaggeration | Invented glasses on a man with none; eyes enlarged; eye color drifted (brown to teal); face 3's climb scene lost the likeness; no bean pouch in one plant scene |
| v2 | Default exaggeration "subtle"; copy the expression; photo is the authority for colors; pouch made prominent | Face 1 good. Face 3's climb scene dropped her glasses and looked young |
| v3 | Added "real age, wrinkles, grey hair" | Over-corrected: a 30-year-old came out ~60 with grey hair and glasses. Reverted |
| v4 | "Exactly the age in the photo, neither older nor younger"; glasses copied both ways; beans now go *in* the hole | Age fixed, scenes faithful; the mini model still added glasses to face 1 |
| final | Same prompt, model changed to `gpt-image-1` with `input_fidelity: high` | Results in the table above |
| v5, v6 | Larger face; accessories carried over; explicit no-boy rule | No improvement on face 7; reverted |

The prompts are generic on purpose: nothing in them describes any particular person. All of the wording is in `src/prompts.js`.

## Cost and speed

`gpt-image-1` at medium quality took about 20 s for a cartoon and about 25–35 s per scene. A full run is three images, so expect roughly 1.5 minutes and a few tens of cents; check your OpenAI usage page for the exact number. `gpt-image-1-mini` is several times cheaper and faster, but it invented and dropped details (see v1 to v4). Switch models with the `IMAGE_MODEL` env var, with no code change.
